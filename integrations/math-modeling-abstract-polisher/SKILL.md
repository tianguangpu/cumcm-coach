# 数学建模论文摘要质量 + 语言润色 + 进度管理大师（Claudecode 智能审查版）

> **对 Claudecode 的执行指令：**
> 1. 论文摘要写完后 / 用户提到「摘要/参考文献/AI味/进度/润色」等任一关键词时，**必须调用本 Skill**。
> 2. 严格按 **§三 4 维审查工作流** 依次运行 4 个工具脚本，任何一维不达标必须修复。
> 3. 所有审查**必须基于代码运行结果**，不得主观判断。修复后再跑一次确认达标。
> 4. 比赛全程可随时调用 **§四 进度看板** 监控节奏，防止超时。

本 Skill 接管「论文写作 → 摘要打磨 → 参考文献升级 → 语言去 AI 味 → 进度管控」的智能审查链路。
**设计目标：消灭国赛评委一眼识破的 4 大写作顽疾——摘要空洞、参考文献老化、AI 腔严重、进度失控。**

---

## 一、什么时候触发调用（**Claudecode 强制触发**）

出现以下任一情况 **必须** 先调用本 Skill：

1. 用户提到关键词：摘要 / 关键词 / 参考文献 / AI 味 / 润色 / 进度 / 倒计时 / 风险；
2. 论文 main.tex 初稿完成，准备打磨质量；
3. 用户反馈「摘要太短/太长」「参考文献不够」「语言像 AI」「时间不够了」；
4. 比赛任何阶段想确认当前进度和下一步该做什么。

**默认约束（Claudecode 不得违反）：**
- 摘要综合得分 < 70 不得交付
- AI 味综合分 < 65 不得交付
- 参考文献前沿度 < 50 不得交付
- 进度看板风险 = CRITICAL 必须立即砍范围

## 三、4 维审查标准工作流（**Claudecode 必须按顺序执行**）

### Step 1：D1 摘要质量审查（国赛占 20%+，最优先）

```bash
# 全量审查（8 维度报告）
py code/check_abstract.py

# 仅看综合得分（快速迭代）
py code/check_abstract.py --score-only

# 输出改进版摘要结构建议
py code/check_abstract.py --fix-suggest
```

**Claudecode 必须理解的 8 维度审查逻辑**：

| 维度 | 检测内容 | 修复方向 |
|---|---|---|
| 5 要素结构 | 问题/模型/方法/结果/结论 是否齐全 | 缺哪补哪，用对应模式词 |
| 字数控制 | 中文 300~1000 字，关键词 3~5 个 | 超长拆段，过短补充 |
| 数值一致性 | 摘要数字 vs results/*.json | 改摘要数字匹配代码结果 |
| 数值显著性 | 每千字 ≥4 个数值 | 补关键指标(准确率/误差/K) |
| 创新点检测 | 强/中/对比 三级创新关键词 | 显式标注"改进了/加权/多证据融合" |
| AI 腔检测 | 摘要特有 AI 用语 | 替换套话为具体表述 |
| 评委打分 | 6 维度加权(问题15/模型25/结果25/创新20/表达10/规范5) | 针对短板补强 |
| 改进建议 | 优先级排序的修复清单 | 按列表逐条改 |

**D1 达标标准**：综合得分 ≥ 70（B 级二等奖水平）
- 若 < 55（D 级）：必须重写摘要，参考 `--fix-suggest` 输出的结构模板
- 若 55~69（C 级）：按改进建议逐条修复，重点补创新点表述和数值

### Step 2：D2 参考文献质量审查

```bash
# 全量审查（8 维度报告）
py code/check_references.py

# 仅看年份分布直方图
py code/check_references.py --hist

# 输出补充 BibTeX 模板
py code/check_references.py --suggest
```

**Claudecode 必须理解的 8 维度审查逻辑**：

| 维度 | 检测内容 | 修复方向 |
|---|---|---|
| 数量类型 | 总数 + J/M/C/D 分布（期刊应≥60%） | 补期刊论文，减教材 |
| 年份分布 | ASCII 直方图，近 5 年占比应≥40% | 删 2000 年前老文献，补 2022-2026 |
| 前沿度 | 加权评分(近1年×1.0→>10年×0.05) | 补近 3 年高被引论文 |
| 外文比例 | 英文条目占比应≥30% | 补 IEEE/Elsevier/Springer |
| 孤立引用 | bib 有无 cite / cite 有无 bib | 删未引用条目或补正文 cite |
| 主题相关性 | 文献标题 vs 论文关键词匹配度 | 删无关经典，补同领域前沿 |
| 经典堆砌 | 同一作者 ≥3 本 = 教材堆砌 | 留 2~3 本核心，其余换期刊 |
| DOI 完整性 | DOI 字段覆盖率应≥80% | Google Scholar 导出 BibTeX |

**支持两种参考文献格式**：
- `.bib` 文件（BibTeX，推荐）
- main.tex 内手写 `\bibitem{}`

**D2 达标标准**：前沿度 ≥ 50，且无孤立引用、无教材堆砌
- 若无 .bib 文件：先用 `--suggest` 生成模板，建立 `paper/refs.bib`
- 若前沿度 < 30：必须补充 ≥5 篇近 3 年期刊论文

### Step 3：D3 语言润色 / AI 味检测（v2.0 对抗升级版）

```bash
# 全量检测（12维度报告 + 修复建议）
py code/polish_text.py --fix-suggest

# 仅看 AI 味综合分
py code/polish_text.py --ai-score

# 仅看 Burstiness（突发性）
py code/polish_text.py --burstiness

# 仅看信息熵
py code/polish_text.py --entropy

# JSON格式输出（供脚本调用）
py code/polish_text.py --json

# 仅检测某节
py code/polish_text.py --section 摘要
```

**Claudecode 必须理解的 12 维度检测逻辑（v2.0 新增 5 维对抗检测）**：

| 维度 | 检测内容 | 修复方向 | 版本 |
|---|---|---|---|
| AI 用语词典 | 5 类 60+ 词条（空话/AI味/机械连接/夸张/冗余） | 按 REWRITE_MAP 逐条替换 | v1 |
| 句长分析 | 平均句长 15~25 字为佳，>35 字 = AI 长句病 | 长句拆短，用句号断开 | v1 |
| 被动堆砌 | "进行了/被...所/得以" 学术腔过重 | 改主动语态 | v1 |
| 重复表述 | 相邻段重复 ≥8 词 = 信息密度低 | 删重复，补新信息 | v1 |
| **Burstiness（突发性）** | 句长标准差/均值，人类 0.5~1.5，AI 0.1~0.4 | **插入超短句+超长句，打破节奏** | **v2** |
| **信息熵** | 字符级/词级熵，中文典型 4.0~5.5 bits/char | **增加用词多样性，避免重复句式** | **v2** |
| **段落对称性** | 段落长度变异系数，AI 段落高度对称 | **让段落长短不一，3~10句不等** | **v2** |
| **句首多样性** | 不重复句首/总句数，AI 句首模式重复 | **避免连续'首先/其次/最后'** | **v2** |
| **机械连接词** | "在此基础上/进一步而言/与此同时" 等 | **删除，用自然过渡** | **v2** |
| 语义流均匀性 | 段落间信息密度变化，AI 过于平滑 | **增加段落间信息密度差异** | v2 |

**v2.0 对抗检测原理（2026 AIGC 检测器会抓的维度）**：

| 检测器 | 检测原理 | v2.0 对策 |
|---|---|---|
| Binoculars | 双模型输出差异 | Burstiness+Entropy 双维度对抗 |
| CoCo | 文本连贯性图谱 | 段落对称性+语义流检测 |
| Burstiness | 句长/复杂度变化 | 直接测量并给出修复建议 |
| 数字水印 | 词元选择统计信号 | 提高用词随机性 |

**典型改写对照（Claudecode 直接套用）**：

| 原句（AI 味） | 改写建议（学术自然） |
|---|---|
| 综上所述，本文... | 综上，本文... |
| 值得注意的是，... | 注意，... |
| 首先进行了...其次进行了... | 一是...二是... |
| 极大地提高了精度 | 精度提高 X% |
| 进行了聚类分析 | 聚类分析... |
| 从上述分析可以看出 | 可见 |
| 在此基础上，进一步... | （删除连接词，直接说） |
| 与此同时，本文还... | 本文同时... |

**D3 达标标准**：AI 味综合分 ≥ 65
- 若 < 50：必须大改，重点修复 Burstiness 和 AI 用语
- 若 50~64：针对超长句、连接词密度、句首多样性修复
- 若 ≥ 65：可交付，但建议继续优化 Burstiness 至 ≥0.4


**Claudecode 必须理解的看板 6 模块**：

| 模块 | 内容 | 决策依据 |
|---|---|---|
| 倒计时 | 剩余时间 + 红黄绿预警 | < 15% 时间 = 红色，立即收尾 |

| 风险评估 | 剩余时间 vs 未完成任务 | CRITICAL = 砍范围 |

| 阻塞检测 | 产出文件长期未更新 | 定位卡点 |

**6 阶段自动检测逻辑**（无需手动标记）：

| 阶段 | 检测方式 | 预计耗时 |
|---|---|---|
| 读题分析 | 题干分析.md / README.md 存在 | 2h |

| 论文写作 | paper/main.tex ≥100 行 | 20h |
| 终稿交付 | paper/main.pdf > 100KB | 8h |

**D4 达标标准**：风险等级 ≤ MEDIUM
- 若 HIGH/CRITICAL：按智能建议加速，必要时砍改进模型部分
- 若 LOW：可继续优化

## 六、失败兜底

1. **摘要提取失败**（check_abstract 报"未找到摘要"）→ 检查 main.tex 是否有 `\begin{abstract}` 或 `\section*{摘要}`，支持 3 种写法自动识别。
2. **参考文献解析失败**（check_references 报"未找到条目"）→ 检查是否有 .bib 文件或 `\begin{thebibliography}`，用 `--suggest` 生成模板建立 .bib。
3. **AI 味评分过低**（polish_text < 50）→ 必须人工重写，不得仅靠自动替换。重点改：摘要、问题重述、模型建立三节的 AI 味。
4. **看板显示 CRITICAL** → 立即按智能建议砍范围：优先保摘要 + 问题 1 + 图表，放弃改进模型。
